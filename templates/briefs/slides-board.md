# Brief: the slides and the board plan

Prepare the slides for a <LENGTH> talk: <SEMINAR>, <DATE>; speaker <SPEAKER>; audience <AUDIENCE>.
Topic: <PAPER> — the mathematics, its formalization and its re-verification. The speaker uses the
blackboard AND a computer, and runs Lean (or the CAS) live. Work only in `slides/` of `<REPO>`.

## Sources of truth (read fully first)
The digest (mathematics and findings register), the formal files (copy Lean code from them only),
the CAS transcripts, and the live demo file `formal/demo/LiveDemo.lean` with its command
`<DEMO COMMAND>` (round trip <N> s; fallback <…>). `cas-verification.md` may appear later: add a
slide if present when you finish, otherwise a placeholder slide marked "pending".

## Deliverables
- `slides/seminar.html`, generated by `slides/build/build.py` from the parts
  `slides/build/NN_*.html` (scaffolded from the skill's `templates/slides/`): reveal.js at
  1280×720 with vendored libraries (`slides/build/vendor.sh`; the deck must work offline),
  MathJax, Lean and Magma highlighting. Code only through SNIP placeholders with text anchors
  (the build refuses non-verbatim code); numbers through COUNT/GREP placeholders; every section
  with `data-timing` summing to the slot; cues BOARD / LIVE / OPTIONAL / PENDING. Structure:
  title; the result in three lines; background; the objects; the proof architecture (the board
  carries the details); what exactly is proved in Lean (statement, axioms); two routes
  (certificate vs `grind`); live demo (command, fallback); CAS re-verification; findings (only if
  the speaker agreed); outlook; references. Speaker notes (press S) carry the minute marks.
- `slides/board-plan.{md,html}`, generated by `slides/build/boardplan.py` from
  `board-plan.tpl.md`: the board panels (what is written where, when it is erased), the timeline
  with the deck's minute marks, a computer run sheet with the live demo and the no-network
  fallback, and a checklist for the day before.
- Run `slides/build/check_render.sh` (headless Chrome, throwaway profile) and fix every reported
  overflow.

## Rules and report
Every number from the digest, a transcript or a log; time and room "to be announced" unless known.
Check the deck in a browser and with headless Chrome screenshots (window at least 500 px wide).
Report the files, the slide count, the timing per segment, and what is pending.
